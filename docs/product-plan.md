# DSH ACE 产品方向（2026-10-19 修订）

本文件是当前生效的产品口径。与旧计划冲突处，以本文为准；旧计划里的代码核查、安装兼容、配置迁移、测试与交付要求继续有效。

## 1. 使命：让普通用户成为 ACE

让所有接触 DSH-ACE 的人类用户，都能从"杂兵"成长为 ACE。用户缺的是术语、经验和任务组织能力，不是想象力、判断力或创造欲。

ACE 要补的是表达与路径：

- 说清以前说不清的想法。
- 看见以前想不到的可能。
- 写出以前写不出的高质量任务。
- 调动 AI 做以前不敢尝试的复杂工作。
- 在用的过程中长出属于自己的判断和方法。

成功标准是用户自己感觉到："原来我也能想到这个、说清这个、做成这个。"

## 2. 主动放大，把选择权交还用户

不能因为用户表达粗糙，就只给平庸、稳妥、最低限度的补全。遇到模糊点子，应当主动推演有价值的可能，形成具体方案，让用户通过选择、否定、修改来定方向。

每次输出要能区分三类内容，用于让用户掌控方案，而不是变成打断创作的确认流程：

1. 用户已经明确表达的目标。
2. 为了形成方案而采用的假设。
3. ACE 主动提出的新增创意。

用户有权选大胆、复杂、高投入、充满未知的方向。ACE 说明取舍，但不把"替用户规避一切风险"当产品目标。

## 3. 四种模式地位平等

| 模式 | 用户意图 | 输出策略 |
| --- | --- | --- |
| 保守安全 | 想稳妥 | 可逆、小步、代价可控的路径 |
| 常规推理 | 想推进 | 直接、有判断力的下一步 |
| 脑暴思维 | 想打开局面 | 跨领域、多路径、有实质差异的可能 |
| 王牌预测（ACE） | 想突破想象边界 | 大胆组合、连续联想、深入展开，产出可继续加工的方案与详细提示词 |

禁止把其他模式暗中收敛成保守模式。不能因为点子复杂、陌生、成本高或有失败可能就自动否定它。

用户的明确限制仍然有效："不要登录"、"预算只有 500 元"是用户的决定；"你最好别做这么复杂"不是模型可以替用户做的决定。

## 4. 王牌预测必须兑现强度

允许：从一个小点子扩成完整系统或新玩法；跨领域迁移机制、组合无关元素；连续举一反三推导二阶三阶可能；挑战当前前提甚至改项目方向；产出可交给其他 AI 直接开工的巨量细节提示词。

篇幅本身不是问题。用户选择充分展开时，不得以"保持简洁"为由压回几条普通建议。质量要求是信息密度、方向差异和可用细节；避免重复，但不限制有价值的展开。

长输出要支持分章节生成、继续展开、局部重写、完整导出。单次输出上限用续写机制处理，不能包装成产品对想象力的限制。

大胆设想可以超前；涉及现实事实时，仍要区分已知、推测、待验证。

## 5. DIY 是用户塑造自己 ACE 的入口

用户可定义自己的思考伙伴：优先看见什么机会、如何挑战惯常想法、从哪些领域找灵感、展开到多深、如何组织最终提示词、保留什么口吻、有哪些禁区或偏好。

支持自然语言创建，例如："别顺着我想。像一个疯批游戏制作人，把我的点子从玩法、心理反馈、社交传播和视觉体验四个方向重新组合，然后写成我能交给 AI 开工的完整任务。"

允许建立一组自己的模式，保存、复制、导入、导出。导出只含模式配置与用户主动加入的示例，不自动附带私人会话。提供真实试用预览，让用户按结果调模式，而不是先学专业参数。

## 6. 两种用途：表达增强与能力扩展

- **表达增强**：用户知道要什么，ACE 帮他说准、说全，并补齐执行所需结构。
- **能力扩展**：用户只有起点，ACE 主动提供他没想到的路线、方法和组合。

两者可切换也可串联：一句粗糙想法 → 多种可能 → 用户选方向 → 深度展开 → 可执行提示词。

不能把所有需求都当润色任务，也不能把每次简单改写都强行扩成大项目。

## 7. 责任边界

ACE 负责：明确展示准备填入或交接的内容；不把猜测伪装成事实；不把新增创意伪装成用户原话；不误投会话、不丢草稿、不把取消后的结果写回；如实呈现成本、状态、失败与输出完整性。

用户负责：选哪个方向、投多少、是否执行、怎么用结果。

减少泛泛的风险提示；只有具体信息影响当前选择时才简短呈现，并尽量同时给出可行路径。"生成大胆方案"与"实际执行方案"分开：生成阶段充分展开；填入、发送、交接遵循用户选择的交互方式，不暗中代替用户操作。

## 8. 验收重点

工程验收之外，增加产品验收：

- **能力提升**：同一句普通输入，ACE 是否补出了用户没表达、但认可且愿意采用的内容？
- **思维突破**：脑暴与王牌模式是否产生真正不同的方向，而不只是把原句写长？
- **可调强度**：用户说"更大胆""继续举一反三""细到能直接开工"时，输出是否明显变化并达到要求？
- **用户掌控**：能否保留某个创意、删掉某个假设、调整局部后重新生成，而不必从头写提示词？
- **小白可用**：不会术语的用户能否用自然语言完成模式创建、方向选择与任务生成？
- **克制与发散由意图决定**：只要改一句话时准确完成；要求疯狂展开时充分展开。

评测要请真实目标用户，以"原始表达"与"使用 ACE 后的任务"对照，看认可度、修改负担和下游 AI 的执行效果。不靠模型自评分宣布成功。

## 9. 与当前实现的差距（2026-10-19 核对）

| 计划要求 | 现在的实现 | 差距 |
| --- | --- | --- |
| 四种平等模式 | **P1 已落地**：`ACE_MODES` 注册表、每模式策略与预算、设置里切换、卡片标注当前模式 | 仍缺按模式区分的候选数量与温度 |
| 保守不得暗中吞并其他模式 | **P1 已落地**：所有模式共用 `CONTENT DISCIPLINE`，显式禁止收敛；测试锁定各模式措辞互不继承 | 需要真实用户对照验证效果 |
| 王牌模式充分展开 | `wild` 预算 6000 tokens（配置上限 8000），仍是单次调用 | P2 的续写/分章未做，当前会被单次上限截断 |
| 表达增强 vs 能力扩展 | 无意图路由，一律走同一套 | 需要在探测意图后选择策略 |
| DIY 模式 | 设置项只有 `enabled/paused/count/autoExpert/mode` | 需要模式定义、自然语言创建、试用预览 |
| 导入导出 | 无 | 需要只含配置与示例的导出格式 |
| 长输出导出 | 无 | 需要完整导出（markdown/JSON） |
| 用户掌控（保留/删除/局部重写） | 卡片只能整体 `Tab` 填入 | 需要按条采纳与局部改写 |
| 成本与完整性透明 | 有 usage 回传，但界面不展示 | 需要呈现 token/耗时/是否被截断 |

## 10. 分期

- **P1 四模式骨架** ✅ 2026-10-19：模式注册表（id/策略/预算）、路由与设置持久化、按模式构建 prompt、UI 选择入口；验收：同一输入在四模式下产出方向可区分，且保守模式不再吞并其他模式。
- **P2 强度与续写**：`更大胆 / 继续举一反三 / 细到能开工` 三档强化指令；超预算时续写并标注"未完成/已续写"；验收：同一点子在两档强度下明显不同，截断可见且可续。
- **P3 DIY 与导入导出**：自然语言创建模式、试用预览、导入导出（仅配置与示例）；验收：不懂术语的用户能在三次交互内做出一个可用模式并导出再导入。
- **P4 掌控与评测**：按条采纳/删除假设/局部重写；真实用户对照评测脚本与记录格式。

## 11. 不做

- 不自动发送、不替用户执行、不把生成当执行。
- 不写会话、不做跨会话学习、不引入遥测。
- 不用统一的保守/简短/繁复风格施加给所有人。
